# BL-06 · Firebase Production Audit

**Sprint:** 3
**Scope:** Firebase Authentication (client + Admin), Firebase Cloud
Messaging, Firestore rules, Firebase Storage rules, service-account
handling.
**Status:** ✅ Audited; safe fixes applied.

---

## Executive summary

Pharma-Exchange uses Firebase in **four capacities**:

1. **Firebase Authentication** — optional social + phone-auth path
   (backend accepts a Firebase ID token; primary auth remains our own JWT).
2. **Firebase Cloud Messaging** — web + mobile push (service worker at
   `frontend/public/firebase-messaging-sw.js`; Admin SDK sends).
3. **Firebase Admin SDK** — token verification + FCM send only (no
   Firestore reads, no direct Storage reads from clients).
4. **Firebase Storage** — pass-through for signed uploads (backend brokers,
   never client-direct).

**Firestore is not used** for business data. PostgreSQL is the source of
truth (per Sprint 3 rules).

## Firebase Authentication

### Client-side (Web SDK)

- Public API key + config are loaded from `VITE_FIREBASE_*` env vars only.
  These values are **not secrets** — Firebase's model treats them as
  identifiers; security is enforced by Auth rules + Admin verification.
- `frontend/public/firebase-messaging-sw.js` embeds the same config for
  FCM registration. This file is regenerated by
  `scripts/generate-fcm-sw.mjs` from `VITE_FIREBASE_*` at build time.

### Server-side (Admin SDK)

- Initialised in `backend/src/config/firebase.ts` **only** with a service
  account loaded from env vars (`FIREBASE_PROJECT_ID`,
  `FIREBASE_CLIENT_EMAIL`, `FIREBASE_PRIVATE_KEY`). No JSON key file is
  ever committed or bundled.
- The private key is stored on Vercel in one-line form with `\n` escapes;
  the code un-escapes them at boot.
- **New in this sprint:** `verifyFirebaseToken()` now passes
  `checkRevoked=true` when `NODE_ENV=production`. Firebase re-checks the
  token against the revocation list — catches disabled/deleted users and
  invalidated sessions.

### Authorized domains

Manual step (Firebase Console → Authentication → Settings → Authorized
domains). Must include:

- `pharma-exchange-frontend.vercel.app`
- Your custom production domain (e.g. `app.pharmaex.bd`)
- `localhost` (dev only — remove for prod-only projects)

## Firebase Cloud Messaging (FCM)

- Backend `sendFcmNotification` (in `notification.service.ts`) uses the
  Admin SDK exclusively. Tokens are stored in the `FcmToken` Prisma table
  keyed by user.
- Frontend registers `firebase-messaging-sw.js` via the Firebase Web SDK;
  the VAPID key comes from `VITE_FIREBASE_VAPID_KEY`.
- Vercel serves the service worker with `no-cache, no-store,
  must-revalidate` (added in this sprint) so old FCM registrations don't
  stick around after a Firebase project migration.

### Token lifecycle

- Registered on first login (frontend calls
  `POST /api/v1/auth/fcm-token`).
- Deregistered on logout and on `messaging/registration-token-not-registered`
  errors from the send path.
- **Recommendation (manual):** enable Firebase Auto-Init token refresh in
  the console so revoked device tokens are cleaned up server-side.

## Firestore rules

Firestore is not used for business data, but the project would fail closed
without an explicit rule set. This PR adds
[`firebase/firestore.rules`](../firebase/firestore.rules) which:

- Defaults to `allow read, write: if false` for all documents.
- Contains a commented `users/{uid}` example for the future.

Deploy with `firebase deploy --only firestore:rules` from the repo root
after linking the Firebase project.

---

## Firebase Storage rules

Uploads flow through the backend (`/api/v1/upload`), which uses the Admin
SDK to issue short-lived signed URLs. Clients never write to Storage
directly. This PR adds
[`firebase/storage.rules`](../firebase/storage.rules) which:

- Denies all direct writes.
- Allows public read only under `/public/*` (used for brand marks / static
  assets).

Deploy with `firebase deploy --only storage`.

## Service-account handling

| Rule | Status |
|---|---|
| Service-account JSON key file committed to git | ✅ Not present anywhere in the repo |
| `FIREBASE_PRIVATE_KEY` exposed to the frontend bundle | ✅ Never referenced in `frontend/` |
| `FIREBASE_*` env vars with the `VITE_` prefix (would leak to browser) | ✅ None |
| Service account has minimal roles | ⚠️ **Manual:** Firebase project → IAM → service account should have only *Firebase Admin SDK Administrator Service Agent* and *Cloud Messaging Admin*. Do not grant *Owner* or *Editor*. |
| Service-account key rotation | ⚠️ **Manual:** rotate every 90 days. Store new key in the Vercel env; delete the old key from Firebase Console → Service Accounts. |
